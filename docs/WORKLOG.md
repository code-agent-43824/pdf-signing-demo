## 2026-09-29 — ручные проверки владельца: целостность CMS и версия CSP

**План.** Владелец прислал результаты ручных проверок 28.09 (релиз до P2-7):
подпись Рутокеном в Firefox отклонена с «CMS-подпись не прошла обязательную
проверку целостности» (`CMS_INTEGRITY_FAILED`), в диагностике CryptoPro CSP
вместо версии — `[object Promise]`, spike CAdES-BES не проведён — слишком
сложно.

1. Записать результаты и план (этот коммит).
2. `[object Promise]`: `getCspVersion()` получает объект версии через
   `About.CSPVersion()`, а в асинхронном API КриптоПро его `toString()` тоже
   возвращает Promise, который код превращает в строку без ожидания.
   Тестовый фейк задаёт `CSPVersion` строкой, поэтому тест дефект не ловил.
   Дождаться `toString()`, добавить регрессию на фейке с async API,
   выкатить.
3. `CMS_INTEGRITY_FAILED`: в ответ уходит только общий код, конкретная
