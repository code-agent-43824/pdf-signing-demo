## 2026-09-24 — ожидание CryptoPro, таймаут Рутокена, гейты CI

**План.** Владелец принял три пункта «Замечено попутно» из `docs/PLAN.md`.
Кроме того, он попросил прекращать ожидание CryptoPro, когда пользователь
переключается на Рутокен. По умолчанию выбран CryptoPro; если его расширения
нет, через некоторое время появляется затемнённый попап «плагин не
установлен» — даже когда пользователь сразу переключился на Рутокен.

Разбор (подробно — в `docs/JOURNAL.md`):

- Попап рисует вендорный `cadesplugin_api.js`. При загрузке он ставит таймер
  (`set_load_timeout`), и если к его срабатыванию плагин не ответил, в
  Firefox показывает оверлей `#cadesplugin_ovr`
  (`show_firefox_missing_extension_dialog`). Отменить таймер снаружи нельзя,
  но оверлей не рисуется, если в момент срабатывания установлен
  `window.cadesplugin_skip_extension_install`.
- Сохранённый выбор плагина не работает с первого коммита.
  `getSavedCryptoStack()` в `public/app.js` сначала читает отмеченную
  радиокнопку, а в `public/index.html` у CryptoPro стоит `checked`, так что до
  `localStorage` очередь не доходит. Каждый новый заход начинается с CryptoPro
  и запускает его таймер.
- Оба эффекта воспроизведены в Firefox 156 без расширения CryptoPro.

1. Тест `isolated worker…`: проверка «процесс завершён» считает зомби
   (состояние `Z` в `/proc/<pid>/stat`) завершённым процессом.
2. CryptoPro. Сохранённый выбор читается раньше значения по умолчанию из
   разметки. `initialize()` адаптера CryptoPro принимает `AbortSignal`:
   переключение на Рутокен прерывает ожидание и ставит
   `cadesplugin_skip_extension_install`. Пока CryptoPro активен, вендорный
   загрузчик ведёт себя как раньше. Тесты адаптера и вендорного загрузчика —
   в `node:vm`, проверка — в Firefox.
3. Рутокен. Ответы расширения и плагина при инициализации (`rutoken.ready`,
   `isExtensionInstalled`, `isPluginInstalled`, `loadPlugin`) ограничены тем же
   сроком, что таймер загрузчика CryptoPro. По истечении срока на плашке
   появляется ошибка, а не вечное «Проверка…».
4. Поиск секретов: gitleaks 8.30.1 по всей истории в CI. Релизный архив
   скачивает скрипт, SHA-256 закреплён в нём же. Локальный прогон по 138
   коммитам находок не дал.
5. Lint и форматирование: Biome 2.5.14 (devDependency) для JS, Ruff 0.16.8
   (отдельный lock с хешами) для Python; `npm run lint` входит в
   `npm run verify`. Код форматируется один раз отдельным коммитом. На сервер
   инструменты не попадают: деплой ставит `npm ci --omit=dev`, а
   `scripts/verify-release.sh` lint не запускает.
6. Каждый шаг, меняющий рантайм, проходит CI и деплой; после деплоя — лог
   job, `health/ready` и соседний сайт.

**Сделано.**

- Шаг 1. `processIsRunning()` в `test/runtime-controls.test.js` считает
  процесс в состоянии `Z` или `X` остановленным; без procfs остаётся проверка

  живым по сигналу 0, а новая проверка видела его остановленным через 0–1 мс.
  Тест прошёл 15 раз подряд. Попутно выяснилось, что тест не ловил поломку,
  которую называет: если убивать только прямого потомка, он всё равно
  проходил, только через 60 с. Добавлена проверка, что операция завершилась
  быстрее 10 с (подробно — в `docs/JOURNAL.md`).
- Шаг 2. `getSavedCryptoStack()` сначала читает `localStorage`, а отмеченную
  в разметке радиокнопку — только если выбора нет. `initialize()` адаптера
