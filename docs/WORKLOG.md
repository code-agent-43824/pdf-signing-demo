## 2026-09-24 — Рутокен в Firefox, шрифты, документация

**План.** Владелец сообщил, что приложение перестало нормально работать с
Рутокен Плагином, и подозревал изоляцию плагинов (PR-10j, `3011186` и
`159f94d`). По его ответам: приложение не видит расширение и плагин, браузер —
Firefox, когда Рутокен работал в последний раз, неизвестно. Кроме того, шрифты
штампа остаются в репозитории (решение владельца), ветку
`claude/vibrant-curie-u8l0q9` владелец удалил, а документацию нужно перевести
на русский и убрать из неё расхождения и ошибки.

Разбор (подробно — в `docs/JOURNAL.md`):

- PR-10j поведения не менял. Код сравнён с `7e80d53`, в Chromium с фейковым
  расширением прогнано 9 сценариев — результаты одинаковые. Production отдаёт
  ровно файлы `main`, серверная обработка CMS после 31.07 не менялась.
- Причина — CSP из PR-8 (`efd707a`, 30.07). Firefox-сборка расширения (MV2,
  1.0.5.0) внедряет свой API двумя inline-скриптами, а CSP страницы без
  `'unsafe-inline'` их блокирует. В Firefox 156 с опубликованным XPI это
  воспроизведено; с SHA-256 этих двух скриптов в `script-src` расширение
  работает. Chrome-сборка (MV3, 1.1.0.0) внедряет API вне CSP страницы и в
  Chromium работает и с текущим CSP, и с исправленным.

1. Добавить оба хеша в `script-src`, закрепить тестом, добавить инструмент
   пересчёта хешей и процедуру обновления в `docs/VENDOR_ASSETS.md`;
   задеплоить и проверить production в Firefox с расширением.
2. Владелец проверяет подпись реальным токеном в Firefox.
3. Записать решение о шрифтах в `CLAUDE.md`.
4. Перевести документацию и убрать расхождения.

**Сделано.**

- Шаг 1 (раскатка): CI для `83fb7e6` прошёл целиком и задеплоил релиз. По
