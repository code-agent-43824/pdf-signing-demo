# Проверка с CryptoPro и Рутокеном в облачном контейнере

Сценарий для агента в облачном контейнере: проверить сайт с настоящими
браузерами, расширениями и плагинами, без компьютера владельца. CryptoPro —
настоящие CSP, ЭЦП Browser plug-in и расширение, сертификат от тестового УЦ
КриптоПро. Рутокен — настоящие Рутокен Плагин и расширение «Адаптер Рутокен
Плагин», а токен заменён форком SoftHSM в режиме fake Rutoken.

## Что проверка доказывает и чего нет

- **CryptoPro** работает целиком настоящий: CSP, плагин, расширение, браузер.
  Ключ лежит в программном контейнере (`HDIMAGE`), а не на токене. Результат
  соответствует проверке на компьютере пользователя с таким же контейнером.
  Он не
  покрывает Windows, ключи на аппаратных носителях через CSP и сертификаты
  аккредитованных УЦ.
- **Рутокен**: настоящие плагин, расширение и браузер, токен эмулирован.
  Всё, что плагин поручает PKCS#11-библиотеке (поиск объектов, PIN и
  счётчик попыток, метка и серийный номер, подпись), — поведение форка, а не
  токена. Такие результаты пишутся как «в контейнере с fake Rutoken», а не
  «на реальном токене». Метки, серийные номера, счётчики PIN и извлечение
  токена по-прежнему требуют реального Рутокена.
- Сайт проверяется на локальном сервере из текущего `main` — это тот же код,
  что в production. Production не меняется.

## Предусловия — решает владелец

1. **Сеть окружения.** Нужны `cryptopro.ru` и `testgost2012.cryptopro.ru`,
   `rutoken.ru` и `download.rutoken.ru`, `clients2.google.com` и
   `clients2.googleusercontent.com` (CRX), `addons.mozilla.org`,
   `dl.google.com`, репозиторий форка, зеркала Ubuntu и `pypi.org`.
   2026-10-16 из облачной сессии этого репозитория отвечали все, кроме
   `github.com`: прокси отдал 403 на репозиторий, не подключённый к сессии.
2. **Дистрибутивы CryptoPro.** CSP 5.0 и ЭЦП Browser plug-in для Linux
   (deb, amd64) cryptopro.ru отдаёт только после входа в учётную запись.
   Владелец кладёт архивы в сессию или задаёт учётные данные секретами
   окружения. В репозиторий, в лог и в отчёт они не попадают.
3. **Лицензия CSP.** Проверить `cpconfig -license -view` после установки.
   Если лицензии нет или срок кончился — серийный номер от владельца через
   секрет окружения.
4. **Пакеты Рутокена.** Страницы загрузки rutoken.ru требуют принять
   лицензионное соглашение. Владелец либо разрешает агенту принять его, либо
   кладёт пакеты в сессию.
5. **Форк SoftHSM.** Владелец называет репозиторий и коммит форка с режимом
   fake Rutoken; его подключают к сессии (`add_repo`) или открывают в сети.
6. **Тестовые ключи.** Закрытые ключи, PIN, CMS и PDF с тестовыми
   сертификатами живут только в контейнере и не коммитятся (`AGENTS.md`,
   §7). В конце работы они удаляются.

## 0. Подготовка

1. `git fetch`, прочитать `AGENTS.md`, `CLAUDE.md`, `docs/STATUS.md`,
   `docs/PLAN.md`, верх `docs/JOURNAL.md`; записать намерение в `docs/PLAN.md`
   и `docs/WORKLOG.md` отдельным коммитом (`AGENTS.md`, §3).
2. Окружение (2026-10-16): Ubuntu 24.04 amd64, root, есть `Xvfb` и
   `xvfb-run`. Браузеры работают с окном под `xvfb-run`; от root Chrome и
   Chromium требуют `--no-sandbox`.
3. Каждое скачанное — в свой пустой каталог в scratchpad; Python, читающий
   скачанное, — с `-I`. Для каждого дистрибутива записать имя, версию и
   SHA-256: они войдут в отчёт.
4. Поставить через apt: `opensc` (`pkcs11-tool`), `libnss3-tools`, `strace`,
   инструменты сборки, которые требует README форка. PyKCS11 — в отдельный
   venv.
5. Браузеры:
   - Google Chrome stable — из `dl.google.com`, `.deb` ставится через apt.
     Фирменный Chrome с версии 137 не принимает `--load-extension`, поэтому
     расширения
     ставятся политикой: файл в `/etc/opt/chrome/policies/managed/` с
     `ExtensionInstallForcelist`, где каждое значение —
     `<id>;https://clients2.google.com/service/update2/crx`. Так ID
     расширения совпадает с магазинным.
   - Chromium (Playwright, `/opt/pw-browsers`) принимает `--load-extension`
     и `--disable-extensions-except` в `launchPersistentContext` без headless.
   - Firefox — сборка Mozilla (tarball или APT-репозиторий Mozilla), не snap.
     Управление — geckodriver или WebDriver BiDi; подписанный XPI ставится
     временно (`install_addon(..., temporary=True)`), как 2026-09-24
     (`docs/JOURNAL.md`).
6. Расширения. Значения проверены по манифестам 2026-10-16:

   | Расширение | ID в Chrome Web Store | Версия | Native host |
   | --- | --- | --- | --- |
   | Extension for CAdES Browser Plugin | `pfhgbfnnjiafkhfdkmpiflachepdcjod` | 1.3.17, MV3 | `ru.cryptopro.nmcades` |
   | Адаптер Рутокен Плагин | `ohedcglhbbfdgaogjhcclacoccbagkjg` | 1.1.0.0, MV3 | `ru.rutoken.firewyrmhost` |

   - CRX:
     `https://clients2.google.com/service/update2/crx?response=redirect&prodversion=154.0&acceptformat=crx2,crx3&x=id%3D<id>%26uc`;
     распаковывается `unzip` (предупреждение о заголовке CRX — норма).
   - Загрузчик CryptoPro ищет расширение по фиксированным ID
     (`public/vendor/cadesplugin_api.js`), а native host пускает только ID из
     своего `allowed_origins`. Поэтому распакованное расширение должно
     получить магазинный ID. У CryptoPro поле `key` в манифесте есть, и ID
     сохраняется сам. У Рутокена его нет: открытый ключ берётся из заголовка
     CRX3. Это поле 2 (`sha256_with_rsa`) protobuf-заголовка, `public_key` —
     поле 1 доказательства. Нужен тот ключ, у которого
     `sha256(ключ)[:16]` в алфавите `a`–`p` даёт
     `ohedcglhbbfdgaogjhcclacoccbagkjg`; он кладётся в `manifest.json` как
     `"key": "<base64>"`. 2026-10-16 так получен именно этот ID.
   - Firefox: XPI Рутокена — ссылка из `docs/VENDOR_ASSETS.md`; XPI CryptoPro —
     со страницы плагина на cryptopro.ru. Версию и SHA-256 обоих записать.
7. Сайт: `PORT=<порт> BASE_PATH=/pdf-signing/ RESULTS_DIR=<каталог в
   scratchpad> node src/server.js`, PATH и Python — как в `CLAUDE.md`,
   «Commands». Production открывать в браузере, только если он доверяет CA
   прокси среды (NSS, `certutil`); проверку TLS не отключать.
8. Каждый шаг браузерного сценария — с записью консоли (`Content Security
   Policy`, `securitypolicyviolation`), ответов `/api/*` и скриншотами в
   scratchpad.

## 1. CryptoPro

### Установка

1. CSP: `install.sh` из архива; `cpconfig -license -view`, версия CSP — в
   отчёт.
2. ЭЦП Browser plug-in: пакеты из архива через apt. Через `dpkg -L` найти
   `nmcades` и манифесты `ru.cryptopro.nmcades.json` для Chrome, Chromium и
   Firefox. Проверить, что `allowed_origins` содержит
   `chrome-extension://pfhgbfnnjiafkhfdkmpiflachepdcjod/`. Для Chromium с
   собственным `--user-data-dir` манифест, возможно, придётся положить и в
   `<user-data-dir>/NativeMessagingHosts/` — проверить и записать, что
   сработало.
3. Добавить origin локального сервера в доверенные сайты плагина, иначе
   плагин спрашивает подтверждение доступа. Способ записать в отчёт.

### Сертификат от тестового УЦ

Тестовый УЦ `https://testgost2012.cryptopro.ru/certsrv/` устроен как
Microsoft CertSrv: `certrqxt.asp` принимает запрос PKCS#10 в base64,
`certcarc.asp` отдаёт сертификат УЦ.

1. Создать контейнер в `HDIMAGE` без пароля и запрос ГОСТ Р 34.10-2012 256
   (`cryptcp -creatrqst`, флаги — по `cryptcp -help`), с назначением ключа
   для подписи. По желанию — второй ключ ГОСТ 2012-512.
2. Отправить запрос через форму `certrqxt.asp` (поля формы взять из её
   HTML), скачать выданный сертификат.
3. Сертификат УЦ — в корневые: `certmgr -inst -store mRoot`.
4. Выданный сертификат — в `uMy` со ссылкой на контейнер
   (`certmgr -inst -store uMy -file ... -cont ...`). `certmgr -list -store uMy`
   должен показать привязку к закрытому ключу.
5. Для подсказки о сертификатах: положить в `uMy` ещё один сертификат без
   ключа (например, копию сертификата УЦ).

| № | Шаг | Ожидаемый результат |

## 2. Рутокен с форком SoftHSM

### Установка

1. Пакет Рутокен Плагина для deb x64 и, если плагин от него зависит, пакет
   rtPKCS11. Через `dpkg -L` найти бинарник native host и манифесты
   `ru.rutoken.firewyrmhost.json`. Проверить `allowed_origins` (Chrome) и
   `allowed_extensions` (Firefox, `rutokenplugin@rutoken.ru`).
2. Узнать, какую PKCS#11-библиотеку грузит плагин: `ldd` по бинарникам
   пакета, затем `strace -f -e trace=openat` на native host, пока расширение
   подключается. Записать путь и способ загрузки.
3. Собрать форк по его README и включить режим fake Rutoken. Подменить
   библиотеку по найденному пути, сохранив оригинал рядом. Если плагин
   вызывает функции, которых форк не реализует, — остановиться и записать
   их в отчёт: это граница проверки, а не повод менять сайт.
4. Инициализировать токен с тестовыми SO PIN и PIN пользователя; метку
   оставить пустой, затем задать — для пункта о метке в `docs/PLAN.md`.

### Ключи и сертификаты на токене

Нужен набор объектов, где у каждого своя роль:

- ключ ГОСТ 2012-256 и сертификат к нему, категория USER;
- тот же тип с `rsa` в CN — регрессия P0-2: алгоритм берётся из OID, а не
  из имени;
- ключ RSA-2048 и сертификат с обычным CN — если форк умеет RSA;
- сертификат ГОСТ без категории (`CKA_CERTIFICATE_CATEGORY` не задан или 0)
  с ключом;
- сертификат категории USER без ключа на токене;
- просроченный сертификат и сертификат только с `keyEncipherment`.

Сертификат к ключу на токене можно сделать самоподписанным или выпустить
локальным тестовым УЦ: средствами форка, OpenSSL с GOST- и PKCS#11-engine или
Python. Категорию задаёт PyKCS11 при записи объекта. Способ записать в отчёт.

| № | Шаг | Ожидаемый результат |

## 3. Итог и записи

- По каждому сценарию: прошёл или нет, на чём упал, путь к скриншоту в
  scratchpad, нарушения CSP (ожидается — ни одного).
- Ошибки сайта исправляются обычным порядком: план, тест, код, проверка,
  деплой.
- `docs/WORKLOG.md` — что сделано; `docs/STATUS.md` — состояние с пометкой
  среды: «контейнер: CryptoPro CSP <версия>, плагин <версия>, тестовый УЦ;
  Рутокен Плагин <версия>, форк SoftHSM <коммит>»; `docs/JOURNAL.md` — что
  узнали; `docs/PLAN.md` — пункты `[x]` или `[!]`. Пункты, которым нужен
  реальный токен, остаются открытыми с пометкой «в контейнере пройдено».
- Удалить контейнеры CSP, тестовые ключи и сертификаты, токен форка,
  скачанные дистрибутивы и учётные данные; убедиться, что `git status` не
  содержит ничего из этого.
