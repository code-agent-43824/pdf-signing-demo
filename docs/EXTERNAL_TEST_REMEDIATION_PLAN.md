Статус выполнения — в `STATUS.md` и `PLAN.md`. Источник — отчёт другого агента,
переданный Кириллом. Это backlog, а не заявление, что все наблюдения независимо

## Приоритет и последовательность

### P0 — риск блокировки токена и ошибочный выбор алгоритма

1. **PIN Рутокена.** Исходный дефект: `dialogs.js` удалял все нецифровые
   символы при вводе и подтверждении; HTML навязывал цифровой ввод.
   Не менять значение молча. Поддержать буквенно-цифровой PIN, если это
   допускает токен/плагин; виртуальную цифровую клавиатуру можно оставить
   как необязательное средство ввода. До `plugin.login` проверить ограничения,
   действительно известные для конкретного токена; если политика длины
   недоступна, не выдумывать универсальный минимум. Невалидный ввод должен
   блокироваться *без попытки логина*, PIN очищаться после операции. Проверить
   `Demo2026pin`, короткий PIN, неверный PIN и счётчик оставшихся попыток на
   безопасном тестовом токене. Не перебирать PIN на личном токене.
2. **Определение алгоритма Рутокена.** Исходный дефект: `isRsaCertificate()`
   и выбор хеша опирались в том числе на `certificate.label`/имя владельца; убрать
   этот эвристический путь. Разбирать OID алгоритма *открытого ключа из DER
   сертификата* (не `signatureAlgorithm` сертификата и не CN), сопоставить
   разрешённые RSA/ГОСТ варианты с опциями `plugin.sign`; неизвестный OID —
   явная ошибка до PIN. Проверить RSA с обычным именем и ГОСТ с `rsa` в CN,
   включая CMS-валидацию результата. Отдельно проверить, что нужный hash
   parameter соответствует фактической версии Рутокен Плагина.

### P1 — корректность результата и обещания интерфейса

3. **Профиль PAdES.** Отчёт указывает на `signing-time` в CMS и отсутствие
   `/M` в PDF. ETSI EN 319 142-1, таблица 1, требует для baseline обратное.
   Сначала воспроизвести на обезличенных PDF от обоих провайдеров и определить,
   может ли каждый provider выпускать CMS без `signing-time` (`addSignTime:
   true` сейчас задан явно у Рутокена). В генераторе PDF добавить корректный
   `/M`; нельзя просто вырезать signed attribute из готовой CMS — это ломает
   подпись. Поскольку изменение затрагивает подписанные байты и может менять
   совместимость, внедрять отдельным срезом с RSA/ГОСТ real-provider gate,
   pyHanko/ETSI conformance и регрессией прежних подписей. До прохождения
   gate не заявлять соответствие PAdES baseline; текущая проверка целостности
   сама по себе этого не доказывает.
4. **Сертификат без ключа.** Рутокен adapter сейчас выставляет
   `hasPrivateKey: true` без проверки. Найти поддерживаемый API для
   сопоставления certId с доступным закрытым ключом; если API не позволяет
   достоверную проверку, не показывать ложное «ключ есть» и до PIN/подписи
   явно предупреждать или исключать неподтверждённый объект. Проверить
   сертификат с ключом и намеренно осиротевший сертификат.
5. **Истечение результата.** Серверный TTL 15 минут оставить как есть.
   Клиенту по `resultExpiresAt` убрать/заблокировать preview и download,
   заменить «файл доступен» на «срок хранения истёк; подпишите заново»;
   обработать HTTP 404/410 и вкладку, пробывшую открытой дольше TTL.
   Проверить переход без перезагрузки и повторный запрос по истекшей ссылке.
6. **URL без конечного слэша.** В production route настроить явный redirect
   `/pdf-signing` → `/pdf-signing/` (с сохранением query при необходимости),
   не меняя работающий маршрут со слэшем. Проверить оба hostname, GET/HEAD,
   статику и отсутствие пустого `200`.

### P2 — предупреждения до необратимого шага и ясность ошибок

7. **Диагностика CryptoPro.** Не называть загрузку локального
   `cadesplugin_api.js` доказательством наличия расширения. Показывать
   проверенные статусы плагина/CSP и состояние «не подтверждено» для
   расширения, если отдельная надёжная проверка невозможна. Вместо
   «дождитесь» дать действие: установить/включить CryptoPro или выбрать
   Рутокен. Disabled «Выбрать сертификат» оформить как disabled визуально,
   курсором и доступностью для клавиатуры/скринридера.
8. **Валидация загрузки.** При выборе файла проверить тип и верхний предел
   **10 MiB** до подтверждения и вызова API; показать предел рядом с upload.
   Серверную строгую проверку сохранить. Предварительно различать явно
   неподдерживаемый/зашифрованный PDF и повреждённый PDF; для owner-password
   файлов выяснить ограничения используемого PDF backend, затем либо
   поддержать их, либо честно объяснить отказ. Не считать MIME единственным
   доказательством PDF.
9. **Ошибки/отмена.** Отмена PIN или подтверждения — нейтральный статус, а
   не «Ошибка». Ошибки JSON настроек штампа показывать локально в открытом
   модальном окне на русском, не под overlay; повторная попытка без потери
   введённых настроек. Коды плагина оставить доступными в диагностике, но
   показать понятный основной текст.

### P3 — качество и семантика интерфейса

10. **Панель PDF.** Сейчас `−`, `+`, `1 / 1`, `100%`, скачивание и печать —
    декоративные элементы. Выбрать один честный вариант: реализовать все
    видимые действия и корректный page count/scale или убрать бутафорскую
    панель и оставить нативный PDF preview. Не оставлять кликабельный вид
    без действия.
11. **Имя и поля.** Формировать безопасное имя результата от исходного имени
    (вместо постоянного `signed-formular.pdf`) и одинаковый Content-Disposition
    и клиентский download name. Проверить происхождение `/Reason`: не
    подставлять издателя сертификата как причину, если пользователь её не
    задавал. Дату истечения в штампе форматировать для человека с понятной
    зоной, не ISO `2027-09-28T13:36:05+00:00`; не менять машинное значение
    сертификата. Проверить Unicode-имена и многоточечные расширения.

## Правила выполнения

- Выполнять **по одному небольшому срезу**, начиная с P0; отдельные commits
  и gates. Этот документ не разрешает массовый рефакторинг или немедленный
  rollout всего списка.
- Для каждого пункта сначала короткий воспроизводимый тест/fixture, затем
  изменение, затем целевая регрессия, полный suite и production gate при
  деплое. Для подписи — real-provider проверка обоих алгоритмов и обоих
  провайдеров там, где применимо.
- Пункты из отчёта, не подтверждённые кодом или воспроизведением, остаются
  **гипотезами до проверки**: фактическая `/M` во всех файлах, owner-password
  PDF, точное поведение production route, источник `/Reason`, политика длины
  PIN конкретного токена. Не тратить реальные попытки PIN ради проверки.
- Этот план не расширяет продукт до проверки доверия, отзыва или статуса
  квалифицированной подписи. Старый `REMEDIATION_PLAN.md` и отдельный
  `CADES_BES_PLAN.md` сохраняют собственные области; новые задачи не считать
  выполненными только потому, что пройден старый криптографический тест.

Нормативный источник: [ETSI EN 319 142-1 V1.2.1, таблица 1](https://www.etsi.org/deliver/etsi_en/319100_319199/31914201/01.02.01_60/en_31914201v010201p.pdf).
